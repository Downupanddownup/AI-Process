# AI Process

`AI Process` 是一个基于 `AutoHotkey v2` 的 Windows 桌面辅助工具。它把"人向 AI Agent 发任务"的过程结构化、版本化、半自动化：帮你管理需求、提示词、回复、实施文档的迭代，减少机械操作，但保留人对每个环节的审阅和决策。

上下文存在你的目录里，不存在任何厂商的对话里——换任何 AI Agent 都不丢失过程。

## 核心工作流程

```
1. 准备：右键目录 → "AIProcess 目录"（或面板上"设目录"/"新主题"/"建问题"）
2. 写需求：人写 需求.txt
3. 发需求：复需求 → 复制提示词（可自动激活 Agent 窗口、粘贴、发送）
4. AI 回应：Agent 创建 v1.md（分析 + 待确认问题），自动在编辑器打开
5. 人作答：建回复 → 基于 v1.md 自动生成带问题骨架的 对v1的回复.txt，逐条填"答："
6. 迭代：复回复 → v2.md … 直至口径收敛
7. 定稿：无新问题时 AI 产出 实施文档.md（需求边界 + 技术方案）
8. 执行：复执行（AI判/步目/改吧 三策略）→ Agent 落地代码 → 完成通知
```

## 当前能力

### 多窗口并行

- `F2` / `F3` / `F4` 三个独立面板，各自绑定主题目录、Agent 窗口和提示词开关，并行处理多个议题互不干扰。
- 每个窗口的会话状态独立持久化，重启后恢复。

### 快捷面板

- 全局热键呼出/隐藏主面板；置顶小窗、托盘常驻、关闭/最小化到托盘。
- 单实例运行：多次启动只保留一个实例，不抢占热键。

### 目录与主题管理

- 资源管理器右键任意文件夹 → **"AIProcess 目录"**，自动设置当前目录并创建/打开 `需求.txt`（后台静默处理，不弹主面板）。
- 面板上"设目录"手动选择、"返"回上级；"新主题"/"建问题"快速创建议题目录。
- 仓库管理：多仓库增删查（`history/repositories.json`），主题归档，历史索引记录进入过的主题目录。

### 版本化沟通

- **建需求**：创建/打开 `需求.txt`。
- **复需求 / 复回复 / 复关系 / 复执行**：复制对应提示词到剪贴板。
- **建回复**：基于最新 `vN.md` 自动提取"待确认问题区"的问题主干，生成带 `答：` 骨架的 `对vN的回复.txt`；支持 `###` 标题/加粗前缀的提问写法（自动剥离），代码围栏内的示例不提取。
- **提问模板**：提示词附带统一提问格式指引，让 AI 的提问结构化、可被工具提取。
- 完整保留每一轮沟通记录（`vN.md` + `对vN的回复.txt` 版本链）。

### 提示词组装

- 提示词模板集中在 `app/templates/`，改文件即生效，无需改代码。
- 主面板"问/实"快捷开关 +【选项】弹窗复选框（打开需求文件 / MD 打开 / 禁止修改约束 / 自动隐藏 / 完成通知 / 提问模板），按需拼装提示词。

### 执行策略与通知

- **复执行**三种策略：`AI判`（AI 判断是否拆解步骤）、`步目`（拆为步骤目录）、`改吧`（直接执行）。
- 执行完成后弹出窗口通知。

### AI Agent 绑定

- **绑窗口**：一键捕获当前活动的 Agent 窗口（标题/进程/类名/HWND），无需手动配置。
- 防呆：拒绝绑定桌面/任务栏/自身；标题自动剥离首尾特殊字符（防 Windows Terminal 图标变化导致失配）。
- 两阶段自愈解析：HWND 优先（带进程+类名校验），失效回退规则匹配，命中后自动更新 HWND。
- 复制提示词后四档动作：不操作 / 仅激活 / 激活并粘贴（默认）/ 激活粘贴并发送。
- 绑定弹窗支持状态查看、测试激活、解绑。

### 编辑器集成

- 编辑器列表由 `app/config/filetools.json` 数据驱动（内置 Zed / IDEA / Trae / VSCode / Sublime / ai-process-editor），默认编辑器可配，新增编辑器只改 json。
- 创建文件、生成 md 后自动用编辑器打开，前台/后台激活方式可配。

### 总结与报告

- 活动记录（jsonl）+ 每日运行日志，全程可观测。
- 经验总结：主题时长统计、历史主题导入、内置 HTTP 查看器（`summary-viewer/`）。
- 独立报告管理窗口（`reports/`）。

### 安装与维护

- `script/install.bat`：创建开始菜单快捷方式 + 注册资源管理器右键菜单。
- `script/uninstall.bat`：清理右键菜单 + 删除快捷方式。
- 安装/卸载需要管理员权限。

## 安装与运行

1. 确保已安装 [AutoHotkey v2](https://www.autohotkey.com/)。
2. 克隆或解压本项目。
3. 双击 `script/install.bat` 安装。
4. 安装完成后：
   - 按 `Win` 键搜索 `AI Process` 启动；或
   - 在资源管理器右键目录 → `AIProcess 目录` 直接启动并设目录。

卸载时运行 `script/uninstall.bat`。

## 配置说明

配置文件位于 `app/config/settings.ini`；编辑器列表位于 `app/config/filetools.json`。

主要配置项：

| 段 | 键 | 说明 |
|---|---|---|
| `App` | `Hotkey` | 呼出主面板的快捷键，默认 `F2` |
| `Hotkey` | `Window2Hotkey` / `Window3Hotkey` 等 | 窗口 2/3 的热键（默认 `F3`/`F4`）与启用开关 |
| `Window` | `Width` / `Height` / `PosX` / `PosY` | 主面板尺寸与位置 |
| `Behavior` | `AlwaysOnTop` / `StartVisible` / `CloseToTray` / `MinimizeToTray` | 置顶、启动显示、关闭/最小化到托盘 |
| `Behavior` | `AutoHideAfterCreate` / `MdActivationMode` | 创建文件后自动隐藏面板；md 打开方式（前台/后台） |
| `Editor` | `IdeaCommand` | 默认编辑器可执行文件路径 |
| `AgentWindow` | `AfterCopyAction` | 复制提示词后的行为档位：1=不操作，2=仅激活，3=激活并粘贴，4=激活粘贴并发送 |
| `Window1` / `Window2` / `Window3` | `CurrentDir`、`Agent*`、各提示词开关、`ExecuteStrategy` | 每个窗口的独立会话状态（由面板操作自动维护，一般无需手改） |

> Agent 窗口的标题/进程/类名特征通过主面板【绑窗口】一键捕获，无需手动填写。

## 设计原则

### 人的职责

AI Process 不替代人做决策，只帮人减少机械步骤。以下事情必须由人完成：

- **定义问题与目标**：只有人知道"为什么要做"和"做成什么样算好"。
- **撰写需求**：`需求.txt` 由人写，AI 不能替人想清需求。
- **价值判断**：这个功能值不值得做、这个方案好不好、这个回复对不对，最终由人判断。
- **审阅与验收**：每一轮 `对vN的回复.txt` 都需要人看过，`实施文档.md` 形成后才能进入执行阶段。
- **确认执行**："复执行"发送的内容需要人先确认，AI 不会自动进入下一轮迭代。

### AI 的职责

AI 适合承担重复性、辅助性工作：

- **生成提示词草稿**：根据模板和上下文拼接提示词。
- **生成回复/代码草稿**：根据人的输入生成 `vN.md` 或实施文档。
- **执行机械操作**：复制、粘贴、按 Enter 发送、创建版本文件、打开编辑器等。
- **提供候选方案**：一次给出多个选项，帮人打开思路。

### 不应该交给 AI 的事

为了降低风险，以下几类操作不会、也不应该由 AI 自动完成：

- **直接修改正式代码**：所有代码修改必须先进入 `vN.md` 或 `实施文档.md`，经过人确认后才能落地。
- **执行有破坏性的系统操作**：删除文件、格式化、改注册表、git reset/push、结束进程等，必须由人显式操作。
- **替人做价值判断**："这个功能不做"、"这个方案更好"这类决策只能由人做。
- **无监督的多轮迭代**：AI 不能自己读回复、自己写下一轮、自己循环，每一轮都需要人触发。
- **在不确定上下文中自动发送**："激活粘贴并发送"档位默认关闭，且需要人先绑定正确的 Agent 窗口。

### 流程原则

- **人在回路**：每一轮沟通都需要人看过、确认过，才能进入下一步。不让 AI 自动闭环。
- **副作用默认关闭**：任何可能修改文件、发送内容、改变系统的操作，默认不执行，需要人显式选择档位或确认。
- **可审计**：`vN.md`、`对vN的回复.txt`、实施文档都保留在目录中，沟通过程可追溯。

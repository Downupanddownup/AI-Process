# 实施文档 — demo 演示方案

> 依据本主题 `需求.txt`、`v1.md`、`对v1的回复.txt`、`v2.md`、`对v2的回复.txt`。定稿：三步、不设 `00`（大纲就是本主题这几轮本身）、一种形态一个子步骤。

## 一、复杂度分析

**业务复杂度：低。** 只跨一件事：把这套演示走完。对象已有——大纲就是本主题已有的五份文件，不需要另写；三种形态的落位、每步产出与验收已在 v2 定死。

**落地复杂度：低。** 零代码、不碰工具。新增三个步骤目录（各含自己的需求与版本链）、一个结果微调目录，最后一份说明文件。外部信息只差一项：说明文件的目录名与文件名由你定。

**唯一需要注意的不是做多少，是不越界**：demo 里不提 demo 之外的事；`.aiprocess` 归工具，不手建。

## 二、是否拆分执行

**拆分，三步。**

- 一种形态一个子步骤是你定的规则，拆开才不会串味。
- 三步各自能独立验收：一步一份产出，不依赖后面两步。
- 结果微调挂在 `02` 下，不单设步骤——它演示的是"执行后发现问题独立立案"，与三种形态不是同一维度。
- 不设 `00-立大纲`：大纲已存在（本主题五份文件），再设一步只会得到一个不演示任何形态的步骤。

## 三、需求边界

**做：**

1. 三个步骤目录：`01-质检形态`、`02-答辩形态`、`03-技炼形态`；每个目录内按 `需求.txt` → `vN.md` → `对vN的回复.txt` 成链。
2. `01`：对大纲跑一次质检码，产出清单（可删／可并／待补证据／术语不一致），每条给位置与理由。
3. `02`：针对大纲出 3–5 题（不给答案）→ 作答 → 逐题评价。
4. `03`：把大纲里的技术点提炼成 2 条，练到能复述。
5. `02/结果微调/01`：把答辩暴露的理解偏差独立立案修正。
6. demo 走完后，在 `AI-Process-Demo/` 下与 `demo` 平级的目录里写说明文件。

**不做（明确排除）：**

- 不加 `00` 步，不另写大纲；
- 不在 demo 里引用 demo 之外的主题、项目或流程；
- 不手建 `.aiprocess/`，不由我代建步骤目录（由步目产生）；
- 说明文件在 demo 走完前不写；
- 不改工具代码。

## 四、技术方案

### 4.1 目录

```
AI-Process-Demo/
├─ demo/                     ← 本主题（流程根）
│  ├─ 需求.txt  v1.md  v2.md  实施文档.md  对vN的回复.txt
│  ├─ .aiprocess/            ← 工具写，不碰
│  ├─ 实施步骤/
│  │  ├─ 01-质检形态/
│  │  ├─ 02-答辩形态/
│  │  │  └─ 结果微调/01/
│  │  └─ 03-技炼形态/
└─ <说明目录>/                ← demo 走完之后才有；名字你定
   └─ 说明文件.md
```

### 4.2 三个步骤怎么跑

每个子步骤是独立对话域，AI 只看当目录——所以**每一步的 `需求.txt` 必须自己写清大纲在哪**，不能指望它记得上级目录。

| 步 | `需求.txt` 写什么 | 用哪个形态 | 产出 | 验收 |
|---|---|---|---|---|
| `01-质检形态` | "大纲＝上级目录的 `需求.txt`、`v1.md`、`v2.md`、`实施文档.md` 与两条回复。对它做一次专项自检：结构是否有冗余、同一件事是否说了两遍、有没有'先说后否'的表述、术语是否一致。输出清单：可删／可并／待补证据／术语不一致，各几处，逐条给位置与理由。" | 质检码 | `v1.md`（清单） | 每条有位置与理由；≥2 条是"可删／可并"这类可执行改动 |
| `02-答辩形态` | "大纲同上。出 3–5 题考我是否真的理解这套演示为什么这么设计，**只出题不给答案**；我作答后你逐题评价。" | 复盘·答辩 | `v1.md`（题）→ `对v1的回复.txt`（答）→ `v2.md`（评价） | 出题轮不含答案；评价逐题给分与依据 |
| `03-技炼形态` | "大纲同上。把里面的技术点提炼成 2 条，每条一句话，练到我能复述。" | 复盘·技炼 | `v1.md`（题）→ 作答 → `v2.md`（评价） | 每条一句话能复述；不得抄大纲原句 |

### 4.3 顺序与依赖

`01` →（**关会话或换窗口，先发一次复关系**）→ `02` → `03`。理由：先质检把大纲挤干净，答辩才考的是干净版本；技炼提炼的是已确认的点。反过来答辩会考到后来被删的内容，演示就成了错误示范。

`01` 与 `02` 之间这一次是复关系唯一的落点：真关掉会话再发，它才有东西可重建。复关系不产文件（段序是 开头段 → 文件清单 → 挂点 → 完成通知），所以它不留产物，效果体现在 `02` 第一轮的题目里。

`02` 跑完后开 `02/结果微调/01`：把答辩里答错或答偏的那一处独立立案、修正——这一步是"意外不被隐藏，也不被放大"的现场。

### 4.4 说明文件

demo 走完（三个步骤 + 一个微调都结束）后再写，位置与 `demo` 平级。内容取自现场，六个必写点：

1. 这里是什么：一个真跑过的演示，只读；
2. 目录结构：为什么是"根 → 步骤 → 微调"三层；
3. 版本链怎么读：谁写谁、谁触发下一份；
4. 日志与统计在哪，哪个数对哪一轮；
5. 约定与内容分开：哪些照抄（文件名、编号、层级），哪些是这次的具体内容、不能照抄；
6. 复关系是哪一轮发生的（`01` 与 `02` 之间那次换会话），以及怎么判断它生效——`02` 的题目是否建立在 `01` 修订后的版本上。

### 4.5 验收

- [ ] 三个步骤目录各成链，层级与编号符合约定（`01-xxx` 下同名 md，微调用两位数字）。
- [ ] 三种形态各出现一次，形态之间不串（每步只有一种）。
- [ ] `02` 的题目建立在 `01` 修订后的大纲版本上；若 `01` 有一条改动而 `02` 仍在考被删掉的那句，判为未重建现场。
- [ ] `02/结果微调/01` 存在，且能看出它修正的是答辩里的哪一处。
- [ ] 说明文件在 demo 走完后才出现，六个必写点齐全。
- [ ] 全程无 `.aiprocess` 手工写入。

# v2 — 技炼：三个点

## 一、单挂点装配：结构写死，内容外置

**设计理念**：每个"动作×策略"的段序写死在代码里，只留**一个**插槽给配置填。配置写歪最多挂错内容，改不出错的段序；代价是新增一种轮次形态必须改代码。

**代码例证**（`app/modules/promptflow/skeleton/Skeleton.ahk`，真实代码）：

```ahk
"复需求|single", [
    Map("kind", "block", "id", "brief"),
    Map("kind", "slot",  "id", "content"),
    Map("kind", "block", "id", "question_format"),
    Map("kind", "block", "id", "end_open_generated")
]
```

同一组合在配置侧只出现一次，且只有一串内容（`flows/builtin/code/flow.json`）：

```json
"复需求|single": { "content": ["complexity", "no_modify", "content_quality", "question_rules"] }
```

`Layouts` 的注释把边界说死了："挂点里挂什么不在本表：那是 flow.json 的事，本表只给位置。"

**提问**：这段装配为什么能把边界划在"只有一个 slot"上？如果允许两个 slot，最先坏掉的会是什么？

## 二、解析引用：只对"没表达"回落，不对"表达错了"回落

**设计理念**：读一个"指向别处"的配置时，文件不存在可以退回默认；文件在、但里面写的东西无效，必须报错。否则用户永远查不到"我的主题为什么换了流程"。

**代码例证**（`app/modules/business/services/FlowResolver.ahk`，真实代码）：

```ahk
if (key = "") {                      ; 文件不存在或为空
    return Map("status", "default", "flowKey", def)
}
if !this.Exists(key) {               ; 写了，但该流程不存在
    return Map("status", "missing", "flowKey", key)
}
return Map("status", "ok", "flowKey", key)
```

文件头注释写明这是硬约束："**绝不静默回落**。只有'文件不存在/为空'才回默认；'写了但流程不存在'必须报 missing。"

**提问**：把这条硬约束改成"缺失就回默认"，会在哪个环节变成查不出来的静默错误？

## 三、按动作声明输入：可见性写在 brief 里，不靠 AI 自己扫

**设计理念**：每一轮 AI 能看到哪些文件，由这一轮的 brief 明确写出；需要"整目录"时另设一个动作承担扫描。输入因此可预测、可审计，代价是没写进 brief 的上下文，它就是看不到。

**代码例证**（三份 brief 原文，真实文件）：

- `briefs/requirement.txt`：只点名一份——"这是一个需求文件，请查看：`{{filePath}}`，并创建 v1.md 作为回应。"
- `briefs/tweak.txt`：一个文件都不点——"做吧，请在完成后将执行结果写入 `{{resultFilePath}}`"。
- `briefs/context_relation_full.txt`：整目录——"当前主题目录…目录中可能存在上述约定之外的非标准文件…这些同样是上下文的一部分"。

**提问**：`复执行·改吧` 的 brief 不带任何文件，这算缺陷还是有意划的边界？若不动它的段序，要让执行轮带上决策信息，最小的改法是什么？

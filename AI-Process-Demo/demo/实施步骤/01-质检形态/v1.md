# v1 — 知道；先把"检什么"对齐

**质检的目的**一句话：在还没动手的时候，用一次独立视角把这一版的水分挑出来——**只出清单，不改稿**。它买的是时机：改动最便宜的时候暴露问题，而不是等落成文件再回头。

所以质检的两个硬约束是这个目的推出来的：产物是清单（不是新版本），每条要能指到位置；它不替你决定删哪句。

## 一、一处要替换

质检码自带的挂载块是代码向的三问（代码结构／重复设计／风格统一）。本步对象是一份文字大纲，三问不贴，等价替换成四项：

| 代码三问 | 换成大纲的四项 |
|---|---|
| 结构反映业务地位 | 结构冗余：同一件事铺垫了两遍 |
| 有无重复设计 | 重复：同一句在两处出现 |
| 风格是否统一 | 术语不一致：同一个东西两个叫法 |
| —（补一项） | 待补证据：说"能省一轮"却没说凭什么 |

## 二、需求文件少了一句

`需求.txt` 没写大纲是哪几份。我按 `01-质检形态.md` 取上级目录那六份（`需求.txt`、`v1.md`、`v2.md`、`实施文档.md`、`对v1的回复.txt`、`对v2的回复.txt`），下一轮质检就以它们为对象。要换范围，你现在说。

## 复杂度初判

- **业务复杂度：低。** 只检一份不到 3 页的大纲，维度已定，不需要新判断。
- **落地复杂度：低。** 产出一份清单，不改上级任何文件；不需要外部信息。

# 维护说明（流程外提示词）

> 给维护这套机制的人——首先是你，AI。改任何文件之前先读这一份；改完按第 5 节验，四步之外不算验过。

## 1 意图

这里是"同一类任务的整套做法"：一条一份正文，人复制它给 AI，开工。

它**不挂载、不参与拼装、与流程零关系**——不进 `flow.json`，不被任何流程引用，流程也看不见它。所以：改它不会影响任何流程；反过来，流程坏了也不该影响它。

## 2 形式

```
app/modules/offflow/
├─ definition/   OffflowPrompt.ahk / OffflowReference.ahk   模型
├─ repository/   OffflowRepository.ahk                        读取（只碰文件）
├─ validation/   OffflowValidator.ahk                         判定（只判对错）
├─ docs/         维护说明.md
└─ data/
   └─ <key>/
      ├─ meta.json      { name, purpose, category, hidden }
      ├─ body.txt       正文，一份
      └─ references/<id>/{meta.json, body.md}
```

`meta.json` 字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 界面显示名 |
| `purpose` | 是 | 这套做法解决什么任务 |
| `category` | 否 | 分类标签，只用于筛选与分组；自由文本，≤12 字；不写＝未分类 |
| `hidden` | 否 | `true` 默认不进取用面板，可直接查看数据或临时切换为可见；取值 `true`／`false`（`1`／`0` 等价），不写＝可见 |

**`hidden` 影响什么**

- 只决定**取用面板列不列它**；不影响文件、不影响复制、不影响校验。隐藏条目可直接查看数据目录，或临时改为 `false` 后在取用面板检查。
- 不写＝可见；写了就按值算。
- 判断路径：数据目录里存在、取用面板没有 → 先查它的 `meta.json` 里 `hidden`。
- `sample` 为什么是 `true`：见第 3 节（它是参照件，不是可直接粘贴的成品）。
- 解除：把 `true` 改成 `false`（或删掉该字段）。

两条硬规则：

1. 正文里的 `{{ref:id}}` **在复制时**换成细则文件的绝对路径；找不到 id 直接报错。
2. 细则（`body.md`）里**不许再写 `{{ref:}}`**——渲染只发生一次，写了就是死字。

## 3 怎么新增一条

1. 在 `data/` 下建目录，**目录名用英文**（key）；中文名写进 `meta.json` 的 `name`。
2. 照 `data/sample/` 的形状抄结构：`meta.json`（`name`／`purpose`／`category`／`hidden`）＋ `body.txt` ＋ 按需的 `references/<id>/{meta.json, body.md}`。
3. 正文里用 `{{ref:id}}` 指细则；细则里不写它。
4. 跑 `CheckOffflow`：报告 `OK`，再打开 `offlow-prompts/<key>.txt` 确认成品干净。

`data/sample/` 是这套形状的**参照件**：结构与任何一条完全相同，只是 `hidden: true`（不进取用面板）。学它的构成，不抄它的内容。

## 4 校验指令的执行规则

```powershell
# 有控制台
app\cli\CheckOffflow.bat [输出目录]

# 无控制台调用（AI 常用）
Start-Process -FilePath "app\cli\CheckOffflow.bat" -ArgumentList '<输出目录>' -WindowStyle Hidden -Wait
```

- 产物分两类：
  - `<输出目录>\offlow-check.txt`：**报告**，只有结论与条目索引；
  - `<输出目录>\offlow-prompts\<key>.txt`：**成品**，内容就是取用时复制到剪贴板的那段——一个字节不加（无标题、无额外换行、UTF-8 无 BOM）。
- 报告通过时：`OK`／`条数：N`／`成品：<目录>`／`条目：a、b`。
- 失败时第一行 `失败 N 条`，随后逐行 `条目 / 文件 / 问题`。
- 每次运行先清空 `offlow-prompts\` 下的旧成品，但**只在确认该目录是本工具创建时才清**：目录里有归属标记 `.offlow-prompts` 才清 `*.txt`（不递归、不删子目录、不删目录）；没有标记就一个文件都不删，报告里写 `成品目录已存在且非本工具创建，未做清空` 并以失败退出，本次也不写成品。
- **成品与渲染的一致性由脚本自己断言**：写完立即读回、与内存结果比对，不等即报 `成品与渲染不一致：<key>`。换行基准 LF。
- **只看产物文件**：stdout 与退出码都不可信（好文件坏文件退出码可能都是 0）。
- 脚本自身出错（语法、找不到 AutoHotkey、60 秒超时）也写同一个报告文件，内容以 `脚本异常` 或 `超时` 开头——"没有报告"只剩一种可能：输出目录不可写，此时退回系统临时目录。

## 5 改完之后怎么验

1. 改正文、细则或 `meta.json`；
2. 跑一次 `CheckOffflow.bat`；
3. 打开 `offflow-check.txt`，确认 `OK`；不 OK 就按行改；
4. 打开 `offlow-prompts\<key>.txt`：它应当**就是**取用时复制到的内容——没有残留 `{{ref:`，路径都真实存在，且没有任何标题或多余空行。

四步之外不算验过。第 4 步最关键：校验器只能证明引用**指向存在**；成品与"复制到的内容"是否同一段字，由脚本的断言担保，人只需确认文件本身干净。

## 6 校验器判的六条

1. `meta.json` 存在，`name`／`purpose` 非空，`hidden` 为 true/false，`category`（若写）非空且 ≤12 字，`key`（若写）与目录名一致；
2. `body.txt` 存在且非空；
3. 每个 `{{ref:id}}` 都能落到一份存在的细则；
4. 细则 `body.md` 内不出现 `{{ref:}}`；
5. 细则目录存在 `body.md`。

## 7 已知边界

- 单条无数量上限校验（人工控制）。
- 校验器不检查正文的**表达质量**，只查结构。
- 没有独立命令行复制入口：复制由取用面板或手工完成。
- 升级前生成过的成品目录没有归属标记，会被拒绝一次（不删任何文件）；换输出目录，或人工确认后放入一份 `.offlow-prompts` 再跑。

# 定位与接收现场

先确认接收方实际看到什么、当时已经知道什么、需要完成什么，再选择必要规则和材料。以下入口路径均相对于 AI Process 项目根目录；复制引用中的正文绝对路径已经能够定位项目根目录。入口存在不代表全部必读。

## 一、中央规则入口

| 当前对象或问题 | 规则入口 | 何时使用 |
|---|---|---|
| 流程块、挂点、流程配方、骨架和导出 | `流程提示词经验.md` | 判断挂点职责、改动位置、组装和导出时 |
| 任意提示词的句子、意图、冗余和接收方困惑 | `提示词编写规范.md` | 审阅具体表达及其对接收者的影响时 |
| 流程外提示词及其正文、细则、复制和维护 | `app/modules/offflow/docs/维护说明.md` | 对象属于流程外方案时 |
| 动作、日志、输入、产物和效果痕迹 | `AI-Process-Demo/演示导读.md` | 还原真实现场或分析是否被响应、是否有用时 |

只读取当前对象和问题需要的入口或章节。回应中说明定位、问题和依据，不把中央规则大段复制给用户。

## 二、流程内提示词

先定位哪套流程、哪个动作、哪个策略，以及对应配方和完整导出结果。分析目标块在完整提示词中的位置、它与骨架及其他块的关系、当轮输入和预期产物，不孤立评审块原文。

需要实际效果证据时，回到具体对话主题，结合目录结构、动作记录、当轮完整提示词日志、输入文件和真实产物还原历史现场。导出结果用于分析组装，真实对话目录用于分析历史使用；预览环境不能冒充真实使用效果。

## 三、流程外提示词

**复制正文**：以 `RenderBody` 的结果为接收文本，其中细则占位符已替换为真实路径。审阅时考虑接收方能否沿路径取得必要细则。

**复制引用**：以公共引用文案的渲染结果为入口，再读取方案正文，并考虑接收方实际选择读取的细则。实际作用来自公共引用文案、方案正文和所选细则，不只看 `body.txt`。

公共包装与方案出现重复、冲突或意图变化时，判断问题属于公共层、方案层，还是两者组合后的边界问题。公共模板影响所有流程外方案，不为修复单个方案而直接修改公共层。

## 四、独立提示词文本

明确接收者、当前任务、已有上下文和预期行为。没有挂点或流程外资产归属时，不虚构目录、配方或动作要求。

## 五、定位不确定时

先给暂定定位、已有依据和缺少的关键材料，允许用户纠正。能够先完成部分审阅的，不因定位信息不完整而全部停下；无法确认的部分标为未知，不用猜测补齐现场。
